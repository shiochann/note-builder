note-builder

ノートを、企画から
セールスレターまで。

「何を書くか」を質問で引き出して、目次を組み、本編を1章ずつ書き、最後に核となる主張を決めてセールスレターを作る。 有料ノート（note / Brain）を作る手順を、Claude Code の質問に答えるだけで進められるスキルです。 できあがった本編はそのまま note に貼れる形で出てきます。Claude in Chrome があれば、エディタへの流し込みと下書き保存までやります。

what is this?

「文章を書いてくれる道具」ではなく
「ノートの作り方を順番に進めてくれる道具」

/note-builder と打つと、Claude が質問を始めます。 誰に売るのか、特典は決まっているか、知識をまとめたファイルはあるか、実績の数字はどれか。 答え終わると、目次 → 本編 → 主張 → セールスレター の順に、あなたの承認を取りながら進みます。

勝手に先へは進みません。目次は納得するまで直せますし、本編は1章ずつ確認してから次に行きます。

📚

知識のまとめ

質問の答えと、すでに持っているファイルを1枚に並べ直したもの。本編の材料になります。

🧭

企画書

特典と目次。ノートの背骨です。修正はここで受けます。

📝

本編（1ファイル）

章ごとに書いて、同じファイルに足していきます。開いて全部コピーして、note に貼るだけ。

🎨

図解の指示書

本編のどこに、どんな図を入れるか。要素とキャプションまで書いてあるので、Canva で作れます。

💌

主張とセールスレター

本編が全部できてから、売るための一本の線を決めてレターを書きます。本編との整合チェック表つきです。

🌐

エディタへ流し込み

Claude in Chrome で note / Brain のエディタを開き、タイトルと本文を入れて下書き保存。公開ボタンは押しません。

the core idea

本編は自由に。
「主張」はセールスレターのために。

本編を「売るための主張」に合わせて書くと、読者に役立つ話が削られます。だから順番を分けています。本編を先に、主張はあとから。

目次 → 本編読者の理解の順番

問題 → 原因 → 解決 → 手順 → 応用。入れたい章は理由を問わず入れます。主張は持ち込みません。

本編が全部できてから
核となる主張レター専用

「○○だけでは△△になる。だから□□が必要」。完成した本編に書いてあることだけを根拠に、一文で言える形にします。
例：「Threads だけだと垢バンで全部消える。だから X も同時に育てる。だから X の伸ばし方を知る必要がある」

根拠 3つ反論と回答敵と味方読者が翌日やること
主張が決まってから
セールスレター最後に作る

実際の本編の見出しから商品説明を書きます。末尾に「主張の各要素をレターのどこで回収し、本編のどこが裏づけか」の表が付き、空欄があるうちは完成にしません。本編に裏づけがなければ、主張のほうを直します。

特典は、いちばん最初に聞きます

特典が決まっているなら、知識を整理する段階から「本編のどこで特典に繋げるか」を織り込みます。決まっていなければ、本編を読んだ人が手を動かすときに欲しくなるものを目次の段階で3案出します。

how to start

置いて、打つ。それだけです。

  1. STEP1

    zip を解凍して、フォルダごと置く

    解凍すると note-builder というフォルダが出てきます。どのプロジェクトでも使えるように、ここへ置くのがおすすめです。

    ~/.claude/skills/note-builder/

    ~ は「自分のホームフォルダ」のことです。Finder で「移動」→「フォルダへ移動」に ~/.claude と入れると開けます。skills フォルダがなければ作ってください。

    特定のフォルダの中だけで使いたいなら、そのフォルダの中の .claude/skills/note-builder/ に置きます。

  2. STEP2

    Claude Code を開き直して、呼び出す

    /note-builder

    「ノート作りたい」「有料 note を書きたい」「目次を考えて」でも起動します。ノートの名前を付けたいときは /note-builder Xの伸ばし方 のように続けて書きます。

  3. STEP3

    質問に答える

    一度に来る質問は 3〜5 個です。数字が曖昧なら「だいたい」で構いません。あとで【要記入】として残ります。知識をまとめたファイルがあれば、その場所を伝えると全部読んでくれます。

  4. STEP4

    途中でやめても、続きから

    /note-builder

    進み具合は _state.md というファイルに残ります。次の日にもう一度同じコマンドを打てば、前回の続きから始まります。

what is .md ?

ただの文章ファイルです。
メモ帳でも開けます。

できあがるファイルは全部 .md という拡張子です。特別なソフトはいりません。中身は普通の文章で、いくつかの記号にだけ意味があります。

#

行の頭の「#」は見出し

# が1つで章タイトル、## で節、### で小さな見出し。note に貼ると見出しになります。

**

「**」で囲むと太字

行の頭の - は箇条書き、> は引用。これ以外の記号はほとんど使いません。

📄

開き方

Mac なら「テキストエディット」、Windows なら「メモ帳」で開けます。Obsidian があると見出しが整って見えます。

note に貼るまでの手順

  • 10_本編.md を開いて、全部選択してコピーします。note の本文にそのまま貼ります。
  • 見出しがちゃんと見出しになっているかを確認します。なっていなければ、その行を選んで note の見出しボタンを押してください。
  • 本文の中の 【図解1｜フロー図】〜 のような行は、画像を入れる目印です。03_図解計画.md の指示書どおりに画像を作って、その行と差し替えます。
  • =====ここから有料===== という行は、有料ラインの目印です。この行を消して、note の「有料エリア設定」をその位置にします。
  • セールスレター（12_セールスレター.md）は、有料ラインより上の無料部分に貼ります。

本編は「章ごとに別ファイル」にはなりません

章ごとに書きますが、書き足していく先は 10_本編.md の1ファイルだけです。コピペが1回で済むように、そうしています。

7 phases

7つのフェーズを、
承認を取りながら進みます。

1
ヒアリング

売る場所、特典、既存ファイル、読者、実績の数字、失敗談。答えはそのまま記録されます。

2
知識の整理

答えと既存ファイルを、読者・実績・知識・失敗談・特典の順に1枚へ並べ直します。抜けがあれば追加で聞かれます。

3
目次と特典案

有料ラインの位置、各章でできるようになること、図解を入れる予定の場所まで入った目次が出ます。納得するまで直せます。

4
本編（1章ずつ）

1回に1章。OK なら本編ファイルに足されます。同時に「ここに、この図解を」の指示書が書かれます。主張には縛られません。

5
核となる主張（レター用）

本編ができてから、候補が3つ出ます。選ぶか、混ぜるか、直すか。根拠は本編に書いてあることだけ。

6
セールスレター

本編の実際の見出しから商品説明を書きます。主張と本編の整合チェック表つき。

7
Chrome でエディタに流し込む（任意）

note / Brain のエディタを開いて、タイトルと本文を章ごとに入れ、見出しの数を照合してから下書き保存。有料ラインの位置と画像の差し替え場所を報告して終わります。公開はあなたが押します。

途中で頼めることの例です。

  • 第3章をもう少し短くして
  • 目次の第2章と第3章を入れ替えたい
  • 主張がしっくりこない。別の案を出して
  • この章の図解、比較図じゃなくてフロー図にして
please read first

できないことも、隠さず書いています。

  • 数字や実績を作りません。 ヒアリングで答えたものだけを使います。答えていない数字は【要記入】として残るので、公開前に埋めてください。
  • 図解の画像は作りません。 「どこに・何を・どんな種類で」の指示書までです。画像は Canva などで作って、目印の行と差し替えてください。
  • 一度に何章も書きません。 1章ずつ確認してから次に進みます。速さより、途中で薄くならないことを優先しています。
  • エディタへの流し込みには「Claude in Chrome」が必要です。 Chrome拡張を入れて、そのChromeで note / Brain にログインしておいてください。ログインは自分で行います（Claude はパスワードを入力しません）。拡張がなくても、本編ファイルを手でコピペすれば同じものが作れます。
  • note の貼り付けは、環境で見え方が変わることがあります。 見出しが変換されなかったときは、その行を選んで見出しボタンを押せば直ります。表は最初から使わない書き方になっています。

one last thing

「わからない」を、そのまま
言葉にして渡してください。

AI を使ううえでいちばん大切なのは、わからないことを言語化して伝えることです。 うまく動かない、書いてある意味がわからない、思っていたのと違う。 それをそのまま言葉にして渡せば、直せます。察してもらう必要はありません。

出てきた文章が自分の言葉じゃないと感じたら、それも伝えてください。 「私はこういう言い方はしない」と一言添えるだけで、次の章から変わります。

伝え方は、このくらいで十分です。

  • 質問が多すぎる。もっと少なくして
  • この主張、読者には刺さらない気がする
  • 本編の文体が固い。もっと話し言葉で

その修正を何度も繰り返していくうちに、これはあなた専用の道具になっていきます。 最初から完成しているものより、そうやって育てたものの方が、ずっと長く使えます。
